# Terminals

## Описание
Приложение для учёта обслуживания кофейных аппаратов.
Замена ведения записей в телеграм-группе (телеграм блокируется в РФ).
Формат: PWA (веб-приложение, открывается как приложение на Android).

## Предыстория
Владелец обслуживает кофейные аппараты лично. При каждом обслуживании записывал информацию в телеграм-группу. Из-за блокировки телеграма в РФ нужна замена — собственное приложение.

## Стек технологий
- **Бэкенд:** PHP 8.2 (системный алиас `php82`), Laravel
- **Фронтенд:** Vue 3
- **Формат:** PWA (Progressive Web App), offline-first — для Android
- **БД dev:** SQLite
- **БД prod:** MySQL
- **Офлайн-хранилище на клиенте:** IndexedDB (для offline-first режима)

## Масштаб
- 18 точек, 18 аппаратов (1:1). Рост не планируется.
- Несколько операторов.

## Формат записи при обслуживании (текущий процесс)
При каждом визите на точку фиксируется:

### 1. Название точки
В большинстве случаев — адрес. Идентификатор точки.

### 2. Количество воды
- Используются кулерные бутылки 18,9 литров.
- Формат записи:
  - `2 полных` — обе бутылки полные (подключённая + запасная).
  - `1+0.4` — подключённая бутылка полная, запасная ~0.4 бутылки (остаток).
  - `1` — только подключённая бутылка, запасной нет.
- Первое число — подключённая бутылка.
- Второе число (если есть) — запасная бутылка.

### 3. Принёс (ингредиенты)
Какие ингредиенты доставлены на точку и сколько. Количество кратно упаковкам.

### 4. Нужно (ингредиенты)
Какие ингредиенты нужно привезти в следующий раз и сколько. Количество кратно упаковкам.

### 5. Комментарий
Произвольный текст. Не обязателен. Используется редко.

### 6. Фотографии (2 шт.)
- Фото внутри аппарата — подтверждение обслуживания.
- Фото снаружи аппарата — подтверждение рабочего состояния при покидании точки.

## Авторизация
- Сессия вечная (без автоматического разлогина).
- Два способа авторизации:
  1. **Через Telegram** — и Login Widget (кнопка на сайте), и через бота (пользователь пишет боту). Оба варианта.
  2. **Включение админом** — админ добавляет/активирует пользователя в приложении вручную.
- Оба способа должны быть реализованы.
- Telegram Bot уже создан, токен будет в `.env`.

## Роли
- **admin** — полный доступ: управление точками, аппаратами, пользователями, ингредиентами, просмотр всей истории, настройки, оприходование товара, загрузка рецептуры, все административные действия.
- **operator** — один интерфейс: запись обслуживания, просмотр/редактирование своих записей, просмотр точек и справочников. Чужие записи видит, но не может редактировать. Свои старые записи — может редактировать.

## UI / UX

### Флоу оператора (главный экран)
1. **Список точек** — главный экран.
2. **Выбор точки** → переход к форме обслуживания.
3. **Форма обслуживания** — заполнение данных (вода, ингредиенты, комментарий, фото).
4. **Сохранение** — локально (офлайн) или сразу на сервер (онлайн).

### Геолокация
- При создании записи обслуживания автоматически фиксируется GPS-координаты оператора.
- Координаты сохраняются вместе с визитом.
- **Координаты точек** хранятся в справочнике (фиксированные, не меняются). Заполняются админом.
- В админке — карта для определения координат точки (указать на карте → сохранить lat/lng).
- Основное назначение: автоматическое определение и отображение ближайшей точки оператору (сортировка списка точек по удалённости от текущей геопозиции).
- Карта / маршрут — не принципиально, не в приоритете.

### Голосовой ввод (транскрибация)
- Оператор может надиктовать голосом, что сделано на точке.
- Речь переводится в текст (Speech-to-Text).
- Текст показывается оператору для проверки/одобрения перед сохранением.
- После одобрения — текст сохраняется как комментарий к визиту.
- **Комбо-режим:**
  - **Онлайн:** Web Speech API (браузерный, бесплатный) — транскрибация в реальном времени.
  - **Офлайн (клиент):** Vosk-browser (WASM, модель ~45 MB, русский язык) или Transformers.js + Whisper tiny (~75 MB). Работают полностью в браузере без сервера.
  - **Офлайн (сервер):** запись аудио локально → при синхронизации транскрибация на сервере через Whisper.php (PHP FFI, codewithkyrian/whisper.php) или whisper.cpp CLI.
- **Настройка пользователя:** режим транскрибации — браузерная (клиентская) или серверная. Если клиентская транскрибация включена, аудио не отправляется на сервер.

#### Исследование: бесплатные STT-решения (только open-source, русский язык)

**Клиентские (браузер):**
| Решение | Офлайн | Размер модели (рус) | Качество | Особенности |
|---|---|---|---|---|
| Web Speech API | Нет | 0 (браузерный) | Хорошее | Бесплатный, встроен в Chrome. Только онлайн |
| Vosk-browser (WASM) | Да | ~45 MB | Среднее | Потоковое распознавание, малый footprint |
| Transformers.js + Whisper | Да | 75-466 MB | Хорошее | WebGPU ускорение, квантизация. Лучший для браузера |
| whisper.cpp WASM | Да | 31-466 MB | Хорошее | Требует SharedArrayBuffer, COOP/COEP headers |
| Sherpa-ONNX WASM | Да | Десятки MB | Хорошее | Streaming + VAD из коробки |

**Серверные (self-hosted):**
| Решение | Платформа | Размер модели | Качество | Особенности |
|---|---|---|---|---|
| Faster-Whisper | Python | 75 MB - 2.9 GB | Отличное | В 4 раза быстрее Whisper, меньше памяти |
| whisper.cpp | C/C++ | 31 MB - 2.9 GB | Отличное | Работает на CPU без Python, квантизация |
| Vosk Server | Python | 45 MB - 1.8 GB | Среднее-хорошее | WebSocket, gRPC, низкие требования |
| Speaches | Python/Docker | 75 MB - 2.9 GB | Отличное | OpenAI-совместимый API, drop-in замена |

**PHP:**
| Решение | Описание |
|---|---|
| Whisper.php (codewithkyrian/whisper.php) | PHP 8.1+, FFI → whisper.cpp. Единственная нативная PHP-библиотека. Composer-пакет. MP3/WAV/OGG/M4A |
| shell_exec + whisper.cpp CLI | Альтернатива — вызов CLI из PHP |

**Рекомендация для проекта:**
- Онлайн → Web Speech API (нулевой размер, бесплатно).
- Офлайн клиент → Vosk-browser (45 MB, потоковый) или Transformers.js + Whisper tiny (75 MB, лучше качество).
- Офлайн сервер → Whisper.php (нативный PHP, без внешних зависимостей) или whisper.cpp CLI.

## Offline-first архитектура
- **Обязательное требование.** Сервер может быть недоступен.
- Все данные для работы (список точек, ингредиенты, незавершённые записи) кешируются на клиенте (IndexedDB).
- Фото сохраняются локально до загрузки на сервер.
- При появлении сети — автоматическая синхронизация с сервером (отправка локальных изменений, получение серверных).
- Конфликты синхронизации: два оператора на одной точке одновременно — практически невозможно, но если случится — обе записи сохраняются как отдельные визиты.

## Хранение фото
- Хранение на сервере (файловая система).
- **Ротация:** для каждой точки хранятся фото только за последние 3 визита. Фото более старых визитов удаляются автоматически.
- **Сжатие (двухуровневое):**
  - **На клиенте:** опционально, вынесено в настройку пользователя (вкл/выкл). Экономит трафик при отправке.
  - **На сервере:** обязательно. Если фото не сжато клиентом — сервер сжимает сам.
- Формат сжатия и целевое качество — определить при реализации (JPEG quality ~70-80%, ресайз до разумного разрешения).
- Места на сервере всегда мало — сжатие критично.

## Ингредиенты
- Список меняется редко. Справочник управляется админом.
- Каждый ингредиент хранит стоимость (за упаковку).
- Учёт складских остатков: сколько упаковок на каждом складе (центральный + точки).

## Распознавание документов по фото
- Загрузка фото документа (накладная, чек, любой документ от поставщика).
- OCR/AI распознавание → извлечение данных:
  - **Название товара** — сопоставляется с номенклатурой. Если товара нет в справочнике, предлагается добавить. При одобрении пользователем — добавляется в справочник.
  - **Количество** — единицы/упаковки.
  - **Цена за единицу**.
- Функция доступна только admin.

- Справочник ингредиентов (CRUD): название, стоимость за упаковку.
- Запись обслуживания: вода, ингредиенты (принёс/нужно), комментарий, 2 фото, геолокация.
- Голосовой ввод комментария (Speech-to-Text) с одобрением.

## Модель данных (черновик)

### Сущности (MVP)
- **User** — id, name, telegram_id (nullable), role (enum: admin/operator), is_active, remember_token, created_at, updated_at.
- **Point** — id, name, address, latitude (decimal, nullable), longitude (decimal, nullable), comment, is_active, created_at, updated_at. Связь 1:1 с Machine.
- **Machine** — id, point_id (unique, FK), model, serial_number, comment, created_at, updated_at.
- **Ingredient** — id, name, unit (по умолчанию "упаковка"), cost_per_unit (decimal, стоимость за упаковку), is_active, created_at, updated_at.
- **ServiceVisit** — id, point_id (FK), user_id (FK), visited_at (datetime), water_main (decimal, подключённая бутылка), water_spare (decimal, nullable, запасная бутылка), comment (text, nullable), photo_inside_path (string), photo_outside_path (string), latitude (decimal, nullable), longitude (decimal, nullable), synced_at (datetime, nullable — для офлайн-синхронизации), created_at, updated_at.
- **ServiceVisitIngredient** — id, service_visit_id (FK), ingredient_id (FK), quantity (decimal), type (enum: brought/needed).

### Будущие сущности (после MVP)
- **Warehouse** — склады (центральный + точки).
- **WarehouseStock** — остатки ингредиентов по складам.
- **Document** — загруженные документы (фото накладных/чеков).
- **DocumentItem** — распознанные позиции из документа (ingredient_id, quantity, price_per_unit).
- **Sale** — данные о продажах (из API аппаратов).
- **Recipe** — рецептуры (какие ингредиенты нужны для каждого напитка).
- **Notification** — настройки и история уведомлений.
