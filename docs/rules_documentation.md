# Правила документации
Тип проекта: кодовый

## Цель
Агент без контекста по `INDEX.md` и одному-трём файлам находит всё нужное для задачи. Полнота и объём достоинством не являются: каждая лишняя строка оплачивается при каждом чтении. Числовых порогов на размер файлов и их количество нет.

## Три класса содержимого
- **Невыводимое из кода** (контракты внешних систем, действующие ограничения, соглашения, назначение переменных, команды, куда смотреть при поломке) — пишется и ведётся руками.
- **Дёшево выводимое** (перечни моделей, маршрутов, контроллеров, методов, полей, структура каталогов) — не пишется; вместо перечня — команда (`grep`, `ls`, `php82 artisan route:list`).
- **Дорого выводимое** (схема БД) — генерируемый артефакт с тремя строками шапки: `Регенерация:`, `Каталог миграций:`, `Маркер свежести:`. Новая миграция — обновить `db_schema.md` и маркер.

## Что пишем и чего не пишем
- Только состояние «здесь и сейчас». Причины выбора, хронология, рассказы об инцидентах не пишутся — для этого есть `git log`.
- Действующее ограничение — не история, оно пишется: отвечает на «что сломается, если сделать иначе».
- Каждое утверждение о коде — с якорем: файл, класс, метод, миграция.
- Один факт — одно место, остальные упоминания — ссылки.
- Бэклог, планы, TODO и заглушки в документацию не попадают.
- Имена переменных окружения не дублируются: перечень — `.env.example`, в документации — только назначение неочевидных.

## Форма
- У каждого файла frontmatter `name` / `description` / `type`; `description` — одна строка, пригодная как строка индекса.
- `INDEX.md` — только строки «путь — когда сюда идти» и раздел «Задача → минимальный набор файлов» (не больше трёх файлов на задачу). В индексе нет дат, счётчиков, статусов и пересказа.
- Крупный предмет — главный файл плюс файлы частностей, на которые он ссылается; частности в индексе не перечисляются.

## Архив
Устаревшее переносится в `archive/` (не удаляется), из маршрутов индекса исключено, остаётся грепаемым.

## Порядок обновления
«Сделано и работает» = «записано»: изменение поведения, описанного в `docs/`, обновляет документацию в том же коммите.
