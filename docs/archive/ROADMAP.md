## Этап 2: Справочники (точки, аппараты, ингредиенты)
**Цель:** CRUD для базовых сущностей.

- [ ] Миграции: `points`, `machines`, `ingredients`.
- [ ] Модели: Point, Machine, Ingredient. Связи (Point hasOne Machine).
- [ ] API-эндпоинты (CRUD):
  - `GET/POST/PUT/DELETE /api/points` — точки.
  - `GET/POST/PUT/DELETE /api/machines` — аппараты.
  - `GET/POST/PUT/DELETE /api/ingredients` — ингредиенты.
- [ ] Валидация: уникальность адреса/названия, обязательные поля.
- [ ] Vue-страницы (админ):
  - Список точек с поиском. Форма создания/редактирования точки.
  - При создании/редактировании точки — карта для указания координат (lat/lng). Leaflet + OpenStreetMap (бесплатно).
  - Список аппаратов, привязка к точке.
  - Список ингредиентов, стоимость за упаковку.
- [ ] Vue-страницы (оператор): просмотр точек (read-only), просмотр ингредиентов (read-only).
- [ ] Seeder: тестовые данные (несколько точек, аппаратов, ингредиентов) для dev.

**Результат:** админ управляет точками/аппаратами/ингредиентами. Координаты указываются на карте. Оператор видит справочники.

**Как проверить:**
- Создать точку с координатами на карте → сохраняется.
- Создать аппарат, привязать к точке → связь 1:1 работает.
- Создать ингредиент с ценой → отображается в списке.
- Зайти как оператор — видит списки, не может редактировать.

## Этап 3: Запись обслуживания (основной функционал)
**Цель:** оператор может фиксировать визит на точку.

- [ ] Миграции: `service_visits`, `service_visit_ingredients`.
- [ ] Модели: ServiceVisit, ServiceVisitIngredient. Связи.
- [ ] API-эндпоинты:
  - `POST /api/service-visits` — создание визита.
  - `PUT /api/service-visits/{id}` — редактирование своего визита.
  - `GET /api/service-visits?point_id=X` — история по точке.
  - `GET /api/service-visits/{id}` — детали визита.
  - `POST /api/service-visits/{id}/photos` — загрузка фото.
- [ ] Vue — форма обслуживания:
  - Выбор точки (или авто-определение ближайшей по геолокации).
  - Вода: два поля (основная бутылка, запасная). Подсказки формата.
  - Ингредиенты «Принёс»: выбор из справочника + количество (упаковки).
  - Ингредиенты «Нужно»: выбор из справочника + количество.
  - Комментарий (текстовое поле).
  - 2 фото: камера устройства (внутри / снаружи аппарата). Превью перед сохранением.
  - Кнопка «Сохранить».
- [ ] Сжатие фото на сервере (Intervention Image или GD): JPEG 70-80%, ресайз до ~1920px по большей стороне.
- [ ] Ротация фото: при сохранении нового визита — проверка количества визитов с фото для точки. Если > 3, удаление файлов фото старейших визитов.
- [ ] Vue — главный экран оператора:
  - Список точек, отсортированный по близости (геолокация).
  - Индикатор: последний визит (дата, кто обслуживал).
  - Переход к форме обслуживания по тапу.
- [ ] Vue — история обслуживания точки:
  - Список визитов (дата, оператор, вода, ингредиенты).
  - Просмотр деталей визита с фото.
  - Редактирование своего визита (оператор). Редактирование любого (админ).
- [ ] Получение геолокации оператора (Geolocation API).
- [ ] Сохранение координат оператора в визите.

**Результат:** полный цикл — оператор выбирает точку, заполняет форму, прикладывает фото, сохраняет. История доступна.

**Как проверить:**
- Создать визит со всеми полями + 2 фото → сохраняется.
- Фото сжаты на сервере (проверить размер файла).
- Создать 4 визита на одну точку → фото 1-го визита удалены.
- Зайти как другой оператор — видит чужой визит, не может редактировать.
- Геолокация: список точек отсортирован по близости.

## Этап 4: Голосовой ввод (транскрибация)
**Цель:** оператор может надиктовать комментарий голосом.

- [ ] Онлайн-режим: Web Speech API.
  - Кнопка «Диктовать» в поле комментария.
  - Распознавание речи в реальном времени.
  - Текст появляется в поле, оператор может отредактировать перед сохранением.
- [ ] Офлайн-режим (клиентский): Vosk-browser.
  - Загрузка модели `vosk-model-small-ru-0.22` (~45 MB) при первом использовании.
  - Кеширование модели в IndexedDB / Cache API.
  - Распознавание локально в браузере.
  - Настройка пользователя: вкл/выкл клиентская транскрибация.
- [ ] Офлайн-режим (серверный): запись аудио.
  - Если клиентская транскрибация выключена и нет сети — записать аудио (MediaRecorder API).
  - Аудио сохраняется в IndexedDB.
  - При синхронизации — отправка аудио на сервер.
  - Сервер: транскрибация через Whisper.php (codewithkyrian/whisper.php).
  - Результат возвращается клиенту для одобрения.
- [ ] Установка и настройка Whisper.php на сервере (composer require, модель whisper-small).

**Результат:** оператор диктует комментарий в любом режиме (онлайн/офлайн). Текст появляется для подтверждения.

**Как проверить:**
- Онлайн: нажать «Диктовать» → говорить → текст появляется в поле.
- Офлайн (клиент): отключить сеть → диктовать → текст распознаётся локально.
- Офлайн (сервер): отключить сеть, выключить клиентскую STT → диктовать → аудио записано → включить сеть → синхронизация → текст появляется.

## Этап 5: Offline-first и синхронизация
**Цель:** приложение полностью работает без сети.

- [ ] Service Worker: кеширование статических ресурсов (app shell, JS, CSS, шрифты).
- [ ] IndexedDB: локальное хранилище данных.
  - Справочники (точки, ингредиенты) — кешируются при первой загрузке / при изменении.
  - Визиты — создаются локально, помечаются как unsynced.
  - Фото — сохраняются как Blob в IndexedDB до отправки.
  - Аудио (если серверная STT) — сохраняются как Blob.
- [ ] Синхронизация (при появлении сети):
  - Отправка unsynced визитов на сервер.
  - Отправка фото и аудио.
  - Получение обновлений справочников.
  - Пометка визитов как synced (synced_at).
- [ ] Детекция сети: `navigator.onLine`, событие `online`/`offline`.
- [ ] UI-индикатор: статус сети (онлайн/офлайн), количество неотправленных визитов.
- [ ] Background Sync API (если браузер поддерживает) — отправка при появлении сети даже если приложение закрыто.
- [ ] Конфликты: визиты — append-only (конфликтов нет). Справочники — сервер-авторитетен (last-write-wins, данные с сервера перезаписывают локальные).
- [ ] Оптимизация: дельта-синхронизация (отправлять/получать только изменения с последней синхронизации, по updated_at).

**Результат:** приложение работает офлайн. Данные синхронизируются при появлении сети.

**Как проверить:**
- Отключить сеть → создать визит с фото → сохраняется локально.
- Индикатор: «Офлайн, 1 визит не отправлен».
- Включить сеть → визит отправляется на сервер → synced_at заполнен.
- Проверить на другом устройстве — визит появился.
- Админ изменил справочник → оператор при синхронизации получил обновление.

## Принципы разработки
- **Offline-first** — каждая фича должна работать без сети или корректно деградировать.
- **Mobile-first** — основное устройство: Android-телефон.
- **Инкрементальная разработка** — каждый этап даёт рабочий результат.
- **Только бесплатные решения** — STT, карты, OCR — без платных API.
