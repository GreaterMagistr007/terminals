# Подсчёт стаканов

Все запросы к таблице `vendista_transactions` для подсчёта стаканов идут через query-scopes модели `App\Models\VendistaTransaction`. Прямой `where('result', 1)` в потребителях запрещён — это ломает идемпотентность и приводит к рассинхрону «что считается стаканом» в разных местах.

## Структура транзакции в Vendista

Поле `status` различает тип записи (внутри `result = 1`):

| status | смысл | sum | reverse_id |
|---|---|---|---|
| 1 | обычная продажа (включая бонусную с `sum=0`) | ≥ 0 | 0 |
| 2 | оригинал, по которому позже был оформлен возврат | > 0 | `trans_id` парного возврата |
| 4 | возвратная запись (отмена платежа) | < 0 (или 0) | `trans_id` оригинала |

`reverse_id` стоит у **обеих** записей возвратной пары и ссылается на парную транзакцию по `trans_id`.

`result != 1` встречается у возвратов с `status=5` (отмена операции на уровне процессинга).

Бонусные продажи: `result=1, status=1, sum=0`. Физически вода налита, рублей не списано.

## Два разных счётчика

### `poured()` — стакан физически налит

```php
VendistaTransaction::poured()  // result=1 AND status != 4
```

Используется для всего, что связано с водой:
- `App\Console\Commands\WaterCheck::calculateWaterMain` — критический уровень для алёрта в Telegram.
- `App\Http\Controllers\Admin\VendistaTerminalController` — поле `sales_since_last_visit`, идущее во фронт; `resources/js/services/waterEstimate.js` умножает его на `WATER_PER_CUP_ML` для отображения остатка.

Включает: обычные продажи, бонусные продажи (`sum=0`), оригиналы возвратов (вода уже была налита, возврат денег этот факт не отменяет).
Исключает: возвратные записи `status=4` (вода физически не лилась).

### `paid()` — финансовая продажа

```php
VendistaTransaction::paid()  // result=1 AND reverse_id = 0
```

Используется только в `App\Http\Controllers\SalesController::today` для страницы продаж за день. Показывает деньги, поэтому исключает обе стороны возвратной пары: и оригинал, по которому был возврат, и сам возврат.

Бонусные транзакции (sum=0) тоже считаются как продажи — они формально успешные, просто бесплатные. Они увеличивают `total_count`, но не `total_sum`.

## Почему один scope не подходит

«Финансовая продажа» и «налитый стакан» расходятся на 641 транзакции (по состоянию на момент введения разделения):

| | poured | paid |
|---|---|---|
| status=1 (обычные + бонусы) | да | да |
| status=2 (оригиналы возвратов) | **да** | нет |
| status=4 (возвраты) | нет | нет |

Если возврат проведён, но оригинал реально налил воду — `WaterCheck` обязан её учитывать, иначе уровень будет завышен и алёрт «мало воды» придёт слишком поздно. А страница финансовых продаж — наоборот: эту операцию нужно вычеркнуть из выручки.

## Вспомогательные scope-модификаторы

```php
scopeForTerminal($id)   // where term_id = $id
scopeAfter($time)       // where time > $time   -- "после визита" (строго)
scopeSince($time)       // where time >= $time  -- "с начала суток" (включительно)
```

Семантика `>` vs `>=`:
- `after` — строго после момента визита (транзакция в ту же секунду уже учтена в зафиксированных остатках воды визита).
- `since` — включительно с момента (для агрегации за сутки от 00:00).

## Правило при изменении

Любая правка определения «что считать стаканом» правит scope в `app/Models/VendistaTransaction.php` и **обязательно** этот документ. Прямые `where('result', ...)` в контроллерах/командах не добавлять — поломаете единое определение.
